# 兑换码清单维护

客户端「兑换码」任务的码**不写在 APK 里**，而是每次执行前从站点拉一份：

```
https://m7a.pages.dev/codes.md
```

改完 `site/codes.md` → 重新部署一次站点 → 所有客户端下次执行兑换任务时生效，**不需要发版**。

---

## 文件格式

```markdown
# 兑换码

## 版本福利 · 长期
- WELCOME7TH

## 3.8 前瞻直播 · 2026-12-31
- STAR2026HAPPY

## 社群限时 · 2026-11-02
- RAIL7THANKS
```

### 分节标题

`##` 开头的一行是一批码的开头，写法和含义：

| 写法 | 分组名 | 有效期 |
| --- | --- | --- |
| `## 3.8 前瞻直播 · 2026-11-15` | 3.8 前瞻直播 | 到 2026-11-15 |
| `## 2026-11-15` | 限时兑换码（默认） | 到 2026-11-15 |
| `## 社群福利 · 长期` | 社群福利 | 永久 |
| `## 长期` | 长期兑换码（默认） | 永久 |
| `## 社群福利` | 社群福利 | 永久（没写日期按长期算） |

- 分隔符用 `·`、`|`、`/`、`：`、`-` 都行，客户端只认 `YYYY-MM-DD` 这个日期格式。
- **认不出日期就按「长期」处理**，宁可贵一个码，也不会把整节码静默丢掉。
- 截止日当天仍然有效，第二天开始客户端自动跳过。过期的码可以留着，客户端会忽略，站点上会置灰显示。

### 兑换码行

- 一行一个码，前面的 `- ` 可以省略。
- 支持字母、数字和汉字（含日文假名、韩文），长度 2~32。
- **含中文的码必须带 `- ` 或 `* `**：没有列表符号的纯中文行会被当成说明文字跳过，防止「有效期至年底」这类句子被误认成码。
- 自动转大写、自动去重。
- `<!-- ... -->` 注释会被整段忽略。

```markdown
## 版本福利 · 长期
- WELCOME7TH
- 永远不会抛弃你     ← 中文码，必须带 "- "
```

### 站点展示

首页「现在能兑的码」一节直接读同一个 `codes.md`，按分组渲染、标剩余天数、过期置灰、点击复制。格式写错时，客户端和网页会同时表现为「少了一组码」，所以改完建议先看一眼首页。

## 注意事项

1. **兑换码是一次性的**。同一个码第二次输入，游戏返回「该兑换码已被使用」。客户端会把它记进本地已兑换列表（`/data/local/tmp/maameow/redeem_used.txt`），下次不再输入。
2. **过期了就删掉或改日期**，别留一堆失效码 —— 用户点「一键兑换」会挨个收到「兑换码无效」，体验很差。
3. **缓存**：客户端有 30 分钟本地缓存；执行任务前会重新拉一次（30 分钟内直接用本地文件）。故障时回退旧缓存，站点挂掉不影响已有清单的兑换。
4. **自定义码**：用户在 App 的「兑换码」配置面板里可以自己加码，存在本地，不会被站点同步覆盖。运营不必为个别人的码改站点。
5. `site/_headers` 已给 `/codes.md` 声明 `no-store`，Cloudflare 边缘不会缓存旧副本。

## 发布流程

```bash
# 1. 改码
vim site/codes.md

# 2. 本地看效果（任意静态服务器）
python -m http.server 8080 --directory site

# 3. 部署（Cloudflare Pages，目录选 site/）
# 4. 线上核对
curl -s https://m7a.pages.dev/codes.md | head -20
```

客户端侧无需任何操作，下次执行兑换任务自动用新清单。
