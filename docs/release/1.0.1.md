## 修复 · 清体力结束后回不到大厅

这是这一版最重要的修复，也是 1.0.0 里"清体力跑完就卡住"的真正原因。

现象：清体力打完最后一场、点完「退出关卡」，程序开始反复"等界面回大厅 → 超时"，
连续 6 轮全部落空，最后报「未能自动回到大厅」。期间游戏可能一直停在某个画面不动。

根因有三层，叠在一起：

1. **点完「退出关卡」后游戏进入加载**，屏幕上是「画面恢复中…」的半透明遮罩。
   此时判态认不出大厅，也找不到任何可点的 ✕
2. 旧代码在这个状态下**按 BACK 想"自救"**。但游戏内 BACK 从来不返回上一级，
   只会弹出「是否退出游戏」确认框
3. 那套自救去认「取消」按钮 —— 而退出框上两个按钮是「**继续游戏**」和「退出游戏」，
   **根本没有"取消"**。所以它每次都：认出了退出框 → 找不到取消 → 放弃 →
   却仍然返回"已处理"，调用方当作"已经回到大厅"继续往下跑

也就是说：这段自救逻辑**从上线起就没成功执行过一次**，它的唯一实际效果是把
退出确认框叠到加载画面上，让后面每一轮都在更糟的状态里重试。

修法（三处）：

- **BACK 整个删掉**。找不到 ✕ 时改为点左上角的「返回」—— 那是真按钮，点空最多没反应
- **新增加载遮罩识别**：命中「画面恢复中」就等它结束（最长 12 秒），不对着遮罩乱点
- **退出框的取消候选加上「继续游戏」**：万一退出框因别的原因出现，现在能真的点掉

顺带：`closeCurrent` 的默认尝试轮次从 4 降到 2（第 1 轮只扫右上角，第 2 轮全屏，
再重复没有新信息）；`backToMain` 改为循环调用 `closeCurrent`，不再透传次数。

## 修复 · 云游戏刚进大厅，邮件任务直接失败

现象：云游戏点「点击进入」进大厅后，第一个任务（邮件）必然报「导航到邮件界面失败」。

根因：刚进大厅时第一次点左上角手机图标，事件发出去了但游戏没反应（云游戏输入延迟
明显大于本地）。旧代码的重试条件是"**先探到遮挡弹窗才重试**" —— 实际上没有任何弹窗，
于是直接放弃。

修法：改成**无条件重试 2 次**，间隔 1.2 秒。实测第二次就能打开。

## 新增 · 启动客户端四选一

「启动游戏」卡片里四个选项平铺，点哪个选哪个，没有二级菜单：

| 选项 | 包名 |
|---|---|
| 官服 | `com.miHoYo.hkrpg` |
| B 服 | `com.miHoYo.hkrpg.bilibili` |
| 国际服 | `com.HoYoverse.hkrpgoversea` |
| 云游戏 | `com.miHoYo.cloudgames.hkrpg` |

- 「本地客户端」文案改为「官服」，但枚举名仍是 `LOCAL` —— 它按名字序列化进
  DataStore，改名会让老用户的启动配置反序列化失败
- 启动流程零改动：非云游戏分支都走本地流程，包名取自任务参数
- 同时把 `TaskChainState.clientType` 改为**优先读任务链里的启动节点**。否则选了
  B 服的用户，引擎层仍会拿 `com.miHoYo.hkrpg` 去 force-stop / 启动 / 盯进程
- 激活向导里那个重复的「选择客户端」步骤已删除（客户端现在只在任务里选）

## 新增 · 自定义任务包

### 一个包一个板块

任务链原来按 `taskType` 去重（同类型只保留第一个），所以装了三个包也只能挂一个
「自定义任务」节点，换包就得改配置。

现在去重键对自定义任务改用 `packId`：同包仍去重，不同包各留一份。装几个包，
「添加任务」里就有几格，加出来的卡片标题就是包名。

导入成功后还会**自动**在任务链里加一个节点，不用再手动去「添加任务」里翻。

### 参数表单

包在 `task.json` 的 `params` 里声明 `key / label / type / default / min / max`，
卡片里按类型渲染控件：

- `bool` → 开关
- `int` → 数字输入（副标题显示范围）
- `string` → 文本框

只存用户**改过**的键，没动过的执行时回落到包里的 `default` —— 这样包升级调了默认值，
用户没碰过的参数会跟着更新。

`min` / `max` 是硬边界，由执行器兜底：填了 999 不会报错，按边界值执行，并在日志里
写一行「参数 times=999 超出 1~10，按 10 执行」。

### 去掉步数与时长上限

- 校验器：`steps` 的 200 步上限移除；`repeat` 的 `times` 上限 20 → 500
- 沙箱：删掉「≤5000 步 / ≤20 分钟」的预算闸，`Budget.tick()` 只保留取消检查
- 保留：`whileExpr` 单条 2000 轮（防条件恒真原地空转）、嵌套 4 层、模板路径闸、
  动作白名单

理由：限制步数挡不住任何恶意流程（真想毁号 9 步就够了），却会把"日常 + 领奖 + 周常"
串成一个包这种正常需求误杀成「执行预算耗尽」。真正的安全边界是结构性的 ——
执行器没有任何启动 App / 执行代码 / 联网 / 越界读文件的能力。

## 已知遗留

- 老版本导入的任务包节点不会自动补板块（补逻辑在导入流程里），需要在「添加任务」里
  手动点一下包名，或者删掉重导
- 左上角「返回」用的是归一化坐标 `(58, 58)`。如果某个二级界面点空了（日志里会有
  `点击区域 左上返回` 但画面没变），需要按具体界面调坐标或改用模板匹配
