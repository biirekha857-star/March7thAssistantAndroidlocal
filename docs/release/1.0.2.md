# 1.0.2

> 发布日期：2026-11-03
> versionCode：13
> 更新方式：**自由更新**（`forceUpdate: false`）

一句话：把几个「点了没反应、任务卡半天」的问题修掉了，另外加了个取坐标的小工具。

这一版的四条修复都来自实机日志里反复出现的同一类现象 —— **不是崩，是静默卡住**：
画面正常、日志没报错，就是一个动作反复做、永远不生效。这类问题比崩溃难查得多，
所以每条下面都写了根因，方便以后遇到类似症状时对照。

## 修复 · 清体力打完后回不到大厅

11-03 两份日志里连续失败 4 次，报「导航到生存索引失败 / 无法回到主界面」。

两个独立的问题叠在一起：

**① 指南页标签整体右移了一格**

游戏更新后，指南页最左边多了一格「新手教程奖励」——这格做完不会消失，只是再打开
指南时游戏会自动跳过它。于是标签栏从 5 格变成 6 格：

```
[新手教程] [每日实训] [生存索引] [模拟宇宙] [逐光捡金] [旷宇纷争]
    0          1          2          3          4          5
```

旧代码按 5 格写死（生存索引 = 第 2 格），点下去落在「每日实训」上 —— 而那是当前
已经选中的标签，画面纹丝不动，重试三次全部落空。

实测证据：截图里高亮框从旧的 x 208~357 变成 343~492，正好右移 135px 一格。

修复分两层：索引整体 +1；同时**保留逐格验证** —— 点一格、用 OCR 确认落到了哪个标签，
不对就换下一格，命中的位置缓存在内存里。游戏以后再动标签栏，不会又这样崩一次。

**② 指南页的 ✕ 一直识别不到**

画面上明明有 ✕，日志却报「未见可点的 ✕」。原因是 `CLOSE_TEMPLATES` 里那两个模板
（`click_close.png` / `close_phone.png`）和这个图形不一样：

| 模板 | 实测分数 |
|---|---|
| `zh_CN/base/click_close.png` | 0.30 |
| `share/plot/close_phone.png` | 0.54 |
| `screen/close_x.png` | **0.874** ← 之前没被用上 |

于是流程变成「找不到 ✕ → 点左上角返回（指南页左侧没有返回按钮）→ 认输」，
每次都在同一个地方放弃。

补上 `close_x.png` 之后，两个问题一起消失。

## 修复 · 退副本时误点「挑战」，又进了一次副本

```
OCR 命中「退出关卡」@(653,947)  → 已点「退出关卡」
已到结算页 → 退出副本
OCR 命中「挑战」@(1669,986)     → 已点「退出挑战」   ← 这里
等待界面 main 超时（3s） ×11 次，卡了 3 分钟
```

退副本会依次试「退出关卡」「退出挑战」。停在**准备页**时，页面上只有一个「挑战」
按钮，而 OCR 的模糊匹配第三级是：

```kotlin
长度 >= 2 && 目标.contains(页面文字)   // "退出挑战".contains("挑战") == true
```

于是它照着「挑战」按了下去 —— 等于重新进了一次副本，之后当然再也回不到大厅。

现在这一级要求页面文字**至少 3 个字**：OCR 漏字通常只漏一两个，短于 3 字的碎片
（「挑战」「确定」这种）不足以证明它就是目标。漏点最多重试一次，错点会改变游戏
状态，两者代价不对等。

## 修复 · 领完委托，弹窗关不掉

反馈是「领完委托回不到大厅，要手动点一下、再点空白处、才能点 ✕」。

根因在 `isRewardPopupOpen()`：

```kotlin
OcrEngine.findText(mat, "获得物品", r)   // 只认这一个标题，只在这个区域里找
```

崩铁不止一种奖励弹窗 —— 活跃度是「获得物品」，**委托奖励是另一套标题**，底部统一
写着「点击空白处关闭」。委托那个永远判成「没有弹窗」，于是：

```kotlin
repeat(3) { if (!isRewardPopupOpen()) return@repeat ... }   // 三次全跳过
```

**一次都没点**。弹窗留在屏幕上，把右上角的 ✕ 挡得死死的。

现在按 5 条特征文字任选其一判断（含「点击空白处」），用全屏 OCR（委托弹窗比活跃度
的矮，框死的区域会漏判），并且连点最多 4 次 —— 奖励展示是两层的，点一下只收起第一层。

## 修复 · 云游戏静音不生效

日志里成片的警告：

```
isPackageInstalled: com.miHoYo.hkrpg not found
getAppUid failed for com.miHoYo.hkrpg
mute com.miHoYo.hkrpg failed - cannot resolve uid
```

但实际跑的是云游戏 `com.miHoYo.cloudgames.hkrpg`。原因：`GameClient.CLOUD` 的
`clientKey` 借用的是 `"Official"`（当时包名表里没有云游戏），于是静音、AppOps、
uid 解析全去操作一个**没装**的包 —— 全都静默失败。

现在 `Packages` 里有独立的 `"Cloud"` 项。

## 新增 · 截一张图取坐标（调试模式）

写任务包最大的门槛是坐标：`tap` 要填 0~1 的比例，作者只能拿截图去量、或者猜一个数
反复试。

第一版试过读 `/dev/input` 记录用户的真实点击 —— 功能能跑（日志里 21 条记录，格式也对），
但**坐标基准是错的**：游戏跑在虚拟屏 1920×1080 上，而手指点的是物理屏 1264×2780，
两者 16:9 vs 20:9，游戏会把 UI 摆在不同位置，归一化之后也对不上。

现在改成截图取点：截的是虚拟屏原始帧，图上点哪儿就是哪儿，中间零换算。

```
设置 → 日志与诊断 → 开启调试模式 → 「截一张图取坐标」
```

可以连着点好几个位置，一次性复制。
